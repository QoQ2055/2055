## 三条反模式（**AI 生图最易犯的"懒惰输出"**）

无论调用 Stable Diffusion / Midjourney / DALL-E / 通义万相 / 即梦 / 文心一格，模型都倾向走最大概率路径，结果三大平庸：

### 1. 创意局限 · 走最安全的视觉解法

模型默认输出"行业常见图"："海报 → 居中字体大标题"、"角色立绘 → 正面站立、清晰背景"、"场景图 → 黄昏 / 暮光 / 蓝紫渐变"。

**破解**：prompt 里**显式拒绝**最常见解法。例：
> "避免传统海报构图：不要居中大字 / 不要从下到上渐变 / 不要 Apple-style 极简白底"

### 2. 构图死板 · 均匀分布 + 居中对称

模型偏好"对称黄金比例 / 黄金分割已用烂"。

**破解**：在 prompt 强制非对称 / 视觉重量不均：
> "构图：主体偏左 1/3，右侧大面积留白用于点缀小元素 / 故意打破对称 / 视线引导线斜向"

### 3. 画面空洞 · 大面积单色 / 无层次

模型生成"看起来对但没东西可看"的图。

**破解**：prompt 主动列出 3-5 层视觉细节：
> "前景：xxx / 中景：xxx / 远景：xxx / 大气层（雾、光斑、粒子）/ 纹理质感（如布料、金属反光）"

## 5 步处理流程（low-freedom · 必走顺序）

```
分析需求 → 识别场景 → 调取创意方法 → 生成设计思路（用户可见）→ 输出 prompt（传下游）
```

### Step 1 · 分析需求

读用户输入，提取：
- **主体**（who / what）
- **载体**（poster / 立绘 / 分镜 / 漫画 / 概念图 / 包装）
- **风格信号**（赛博朋克 / 古风 / 油画 / 极简 / 商业插画）
- **使用场景**（社交媒体头图 / 章节插画 / 角色档案）

### Step 2 · 识别场景子类

按 FLIL 应用域分类（**不要套用 limtdesign 的"营销物料"分类**，那不是我们的用例）：

| 子场景 | 典型需求 | 关键 prompt 字段 |
|---|---|---|
| **角色立绘** | 主角 / 配角档案 | 服装层次 + 表情微妙度 + 视线方向 + 站位非正面 |
| **场景图** | 章节插画 / 叙事氛围 | 时间 / 天气 / 光源 / 视点高度 / 中景层次 |
| **分镜图** | 短剧分镜板 | 镜头语言（POV / OS / 特写 / 全景）+ 动作瞬间 + 情绪标签 |
| **漫画分镜** | 番外内容 | 格子分割 + 对白气泡占位 + 网点 / 色调 |

### Step 3 · 调取创意方法

针对识别的子场景，**应用上述 3 条反模式**作为 prompt 前缀：
- 加 negative prompt：拒绝平庸视觉
- 加 composition 指令：强制非对称
- 加 detail layers：列前/中/远景细节

### Step 4 · 生成设计思路（可见给用户）

**先输出文字版设计思路**让用户审：
> "本图设计：构图斜对角主体偏左下，主角侧脸 3/4 视角，背景为黄昏古城轮廓（远景）+ 飘飞落叶（中景）+ 主角佩剑反光（前景），色温暖中带冷蓝点缀..."

用户确认 / 调整后再到 Step 5。

### Step 5 · 输出 prompt（传下游）

按目标模型语法（Midjourney 用 `--ar`、SD 用 `(...)`、通义万相用 JSON）生成 final prompt。**不要直接把 Step 4 的中文设计思路灌给模型** —— 转译为模型最喜欢的 keyword + weight 形式。

## 与本仓现有结构的关系

- **数据存储**：图生图 prompt 应入 `data/prompts/` 体系（如 `data/prompts/character-portrait.json`），与 LLM prompt 一致管理
- **运行时**：调用方应在 `src/store/...` 接 OpenAI-compatible image API（参考 LLM 调用模式）
- **UI**：未来生图 epic 启动时，UI 入口应在角色 / 章节 详情页加按钮，遵循 `karpathy-guidelines.md` 的 surgical change

---

## 反模式（**本 skill 自身禁止**）

- ❌ **直接装 limtdesign 的 `scenes/` 子文件**：那些是 poster/banner/social media 营销物料模板，FLIL 是叙事影像，**不复用**
- ❌ **建议自动调用图生图 API**：所有生图必须用户点击触发（与 `coding-standards` ADL stability-first 一致）
- ❌ **跳过 Step 4（设计思路）直接出 prompt**：用户失去审阅机会，prompt 一旦烧 token 就回不去
