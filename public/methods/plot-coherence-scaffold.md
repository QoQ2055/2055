# 情节连贯性脚手架（ATU / Propp 母题的反散架守则）

> **来源**：用户上传《ATU 簇缺乏主线与支线结构的问题诊断与解决方案》，综合 STORYTELLER (ACL 2025) / SCORE (Khatun & Brown 2024) / RANLP 2023 的研究结论整理。
> **定位**：工艺层 · **与所有结构骨架正交**（与 ATU 301 / 英雄之旅 / Save the Cat / 三幕式 / 起承转合 **不互斥，可叠加**）。
> **价值**：防止 AI 生成长文时"前后矛盾 / 伏笔遗忘 / 人设漂移 / 虎头蛇尾 / 情节散架"。

---

## 适用边界

✅ **强烈推荐启用**：
- 长篇（50 万字以上）/ 超长篇（100 万字+）/ 连载文
- 伏笔密度高 / 多线并进 / 角色多于 5 人
- 用了 ATU 301 / 英雄之旅等骨架，担心母题之间缺因果粘合

✅ **可选启用**：
- 中篇（10–30 万字）有多条支线
- 短篇单线叙事启用收益小（本模块价值在长距离追踪）

❌ **不建议**：
- 极短篇（< 3 万字）—— 单线短跑，上这个模块反而增加注入开销
- 散文化 / 意识流 —— 这类风格本就不追求严格因果，强上会僵化

---

## 一、问题清单（LLM 自检用）

每次生成新内容前，先自查是否会引入以下问题：

| 问题 | 典型表现 | 避免方法 |
|---|---|---|
| **情节跳跃** | A 发生后直接跳到 D，缺 B→C 铺垫 | 因果链硬律（下节） |
| **人设矛盾** | 第 3 章说"我恨蛇"，第 8 章却养蛇 | 角色状态知识库 |
| **设定冲突** | 第 1 章"世间唯一"，第 10 章出现复制品 | 一致性校验 5 条 |
| **主题漂移** | 开头"复仇"，三章后变"爱情"，五章后变"冒险" | 核心主题锁定（首章定调） |
| **重复堆砌** | 相似情节单元反复出现，无递进 | 情节节点去重 + 密度分布 |
| **虎头蛇尾** | 开局精彩，后续无力 | 分层规划 + 伏笔回收率 |
| **伏笔遗忘** | 埋了线没回收 | 伏笔回收节点标注（硬律） |

## 二、三条因果链硬律（必须遵守）

### 硬律 1 · 每个情节节点必须嵌入「因为 … 所以 …」

任何 ATU 母题 / 情节事件，**必须能回答**：

- **前因**：为什么此刻发生这件事？它回应了前文哪一次铺垫？
- **后果**：它制造了哪些新状态？影响后续哪一章的哪件事？

**LLM 输出时的具体形态**：
生成大纲或章节明细时，每一条情节点后加一行小字元数据（这些元数据面向 LLM 自己，最终章节正文可不暴露给读者）：

```
• 主角发现假师兄的信物
  ↳ 前因：第 N 章 C4 簇（师父赠予信物）
  ↳ 后果：第 N+5 章 F3 簇（信物成为假英雄的破绽）
  ↳ 状态变更：主角.怀疑对象 += 师兄；师兄.警觉 += 40%
```

### 硬律 2 · 角色状态必须跨章一致

写每一章时，**必须**先读取或回忆所有出场角色的已建立状态（憎恶/偏好/誓言/创伤/能力/持有物）；新事件不得**无理由违反**这些状态。

**允许的状态变更**只能通过以下三种情况触发：
1. **显著事件** 触发（如救命之恩 → 从敌变友，须有清晰转折章节）
2. **时间累积** 触发（如十年磨炼 → 技艺精进，须有跨度说明）
3. **外力干预** 触发（如失忆 / 操控 / 神启，须是剧情已埋的设定）

**未经上述三种触发的人设突变 = 不合格**。

### 硬律 3 · 伏笔必须有回收节点

在大纲阶段每埋一处伏笔，**立即**标注预计回收的章节区间：

```
伏笔：主角左臂的青色胎记（首章出现）
  ↳ 回收节点：第 40–45 章（身世揭露段）
  ↳ 关联 ATU 母题：F5 身份揭露
  ↳ 若 45 章前未回收，触发修复机制（插入回收）
```

**伏笔回收率目标 ≥ 90%**。结尾阶段 LLM 必须回顾所有未回收伏笔，在最终 3 章内补齐或主动删除。

## 三、分层规划（三层骨架）

新增 / 修改任何情节前，都要确认它在三个层级都自洽：

### 宏观层（Macro · 整本书）
- 核心主题（一句话）
- 结构骨架（从本项目已启用的结构类方法论模块继承，如 ATU 301 / 英雄之旅）
- 主线与支线拓扑（主线 1 条、支线 ≤ 3 条，每条支线要标注合流章节）

### 中观层（Meso · 每一卷 / 章节群）
- 该卷承担的主题子命题
- 该卷绑定的 ATU 母题簇（由结构骨架模块产出）
- 该卷的核心因果链（3–5 组"因为…所以…"）

### 微观层（Micro · 每一章 / 场景）
- 该章 / 场景服务的中观命题
- 该章的**场景功能单元**（SFU）：每个场景必须回答"这个场景推动了哪条因果链？"
- 悬念钩子：本章结尾必须**留至少一个未解悬念**（章末钩子），否则章节合格率不达标

**关键原则**：下级生成必须**回馈上级校验**。写第 17 章时不能违背第二卷的核心因果链，也不能违背整书主题。

## 四、动态情节节点 · 元数据模板（进阶用法）

在分卷规划 / 分章大纲输出时，**建议**每个重要情节节点附加一块结构化元数据（注：这是给 LLM 自我校验用的，最终章节正文不必呈现）：

```yaml
情节节点:
  atu_code: "ATU 313C"   # 若项目使用 ATU 骨架
  skeleton_stage: "B3 · 第二重试炼"   # 或 Save the Cat 的 beat id
  causal_dependencies:
    requires: ["第 5 章 B1 簇 · 赠礼者登场"]   # 前置必备
    produces: ["第 12 章 C3 簇 · 获知弱点"]   # 后续产物
    forbidden_conflicts: ["主角.能力 < 觉醒值 50"]   # 禁止前置失败
  character_state_changes:
    主角: ["能力 + 50", "持有物 += 真火符"]
    配角A: ["好感 - 20", "怀疑值 + 30"]
  theme_binding: "勇气与牺牲"
  foreshadowing_sow: ["主角对真火的恐惧"]   # 此节点埋的伏笔
  foreshadowing_recycle: "第 38 章"   # 预计回收章
```

**最小可执行版**（若 tokens 紧张，允许只保留以下 3 项）：
- `requires` + `produces` + `foreshadowing_recycle`

## 五、一致性校验 5 条（生成前自检）

新生成任何段落前，先扫描前文，检查是否冲突：

1. **唯一性冲突**：前文声明"世间唯一 / 独一无二"的对象，本次不得出现第二件
2. **角色誓言冲突**：前文已立誓（如"绝不再动刀"），本次让其动刀必须有合法破誓事件
3. **世界规则冲突**：前文已定规则（如"元婴期才能御剑飞行"），本次不得允许筑基期角色御剑
4. **时间线冲突**：跨章时间推进要连贯（不得第 5 章说"三天后"，第 6 章却说"半年后"未说明跳跃）
5. **物品属性冲突**：魔法物品属性（攻击/防御/次数限制）一经设定不得变更，除非有强化 / 损坏剧情

**命中任一冲突** = 该段内容不合格，须重写或补充转折说明。

## 六、情节密度分布（波浪式要求）

避免平铺直叙，每卷内部应遵循：

```
卷内情绪 / 事件密度曲线（以一卷 40 章为例）：

  ▲ 密度
  │         ╭─╮        ╭──╮
  │     ╭──╯   ╲       │  ╲
  │    ╱         ╲    ╱    ╲
  │  ╱            ╲__╱      ╲___▲ 卷末大爆点
  │╱
  └─────────────────────────────► 章节
   1   5    10   15   20   25   30   35   40
```

- 每 8–12 章必须有一个**小高潮**（情绪锚点 / 阶段性胜利 / 重大转折）
- 每卷末必须有**卷末大爆点**（最高强度事件，拉动读者追下一卷）
- 两个高潮之间必须有**蓄势低谷**（角色自省 / 感情升温 / 日常铺陈），不能连续高强度

## 七、生成流程三阶段（落地操作）

### 阶段 1 · 规划（novel.2.1 / 2.2 / 2.3 节点）

- [ ] 确立核心主题（一句话）
- [ ] 绑定结构骨架（继承已启用的 structure 类方法论模块）
- [ ] 每卷绑定 ATU 母题簇 / 骨架节拍
- [ ] 为每个情节节点标注因果依赖（requires / produces）
- [ ] 建立角色状态知识库初始值
- [ ] 所有伏笔标注预计回收章节

### 阶段 2 · 生成（novel.3.1 草稿节点）

- [ ] 每章开头承接上章结尾的因果状态（不做无理由跳跃）
- [ ] 新 ATU 母题激活时写出因果依据
- [ ] 在规定节点主动回收伏笔
- [ ] 角色行为通过状态校验 5 条
- [ ] 章末留至少一个未解悬念

### 阶段 3 · 校验（novel.3.2 润色节点）

- [ ] 扫描本章是否触发一致性 5 条冲突
- [ ] 本章是否合格地推进了上级因果链
- [ ] 是否引入未标注回收的新伏笔
- [ ] 密度 / 节奏符合波浪式要求

## 八、与其他模块的协同

- **与 ATU 301 / 英雄之旅 / Save the Cat / 三幕式 / 起承转合**：叠加使用。结构骨架提供"每一卷 / 章做什么"，本模块提供"母题之间怎样不散架"。
- **与 MBTI 五步法**：角色状态知识库可直接复用 MBTI 角色卡的"核心恐惧 / 行动逻辑 / 剧情功能"字段。
- **与 Pixar 22 法则**：Pixar 的"角色欲望 vs 真正需要"可直接挂到因果链元数据的 `theme_binding` 里。
- **与 七情节奏点**：七情节奏点管**单章情绪**，本模块管**跨章因果**，完美互补。
- **与 视听语言脱水法**：完全正交。本模块管"写什么"，脱水法管"怎么拍"。

## 九、不合格反例

- ❌ 情节节点只写"主角找到宝剑"，不交代前因后果（违反硬律 1）
- ❌ 第 3 章说主角恐血，第 15 章毫无铺垫地在血池里畅游（违反硬律 2）
- ❌ 埋下"主角左臂胎记"伏笔但全书结束未回收（违反硬律 3）
- ❌ 第 1 章声明魔剑"世间唯一"，第 20 章反派拿同款（违反一致性第 1 条）
- ❌ 每章都是高潮，没有蓄势章（违反密度分布）
- ❌ 章末情节收束干净，没有悬念钩子（违反微观层要求）
