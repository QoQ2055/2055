# 事件驱动法（Event-Driven · 由外向内 · 先设局后入人）

> **来源**：墨香阁柒爷网文创作课《故事三驱动》第八课。
> **定位**：driver 层 · **故事引擎选择型模块**（与 character-driven / emotion-driven 互斥 · 一个项目同时只选一种主驱动）。
> **核心价值**：当主线故事的看点是**悬念 + 逻辑 + 极限求生**而非"人物魅力"或"情绪宣泄"时，启用本模块让 LLM 围绕**精密事件结构**展开，每个角色都为推进谜题服务。

---

## 适用边界

✅ **强推荐启用**：
- 悬疑推理（柯南 / 福尔摩斯型）
- 灾难片 / 末日题材（流浪地球型）
- 硬科幻（三体型）
- 反乌托邦 / 阴谋论
- 电影改编 / 短篇小说

⚠ **可选启用**（次优）：
- 武侠 / 仙侠（如果有大谜局）
- 都市职场（如果是商战 / 律政）
- 短剧（部分悬疑短剧）

❌ **不要启用**（错配）：
- 大女主 / 大男主成长剧（应选 character-driven）
- 言情向 / 情感向（应选 character-driven 或 emotion-driven）
- 付费爽文（应选 emotion-driven）
- 系统流（人物 = 工具 · 但事件也较弱）

---

## 核心心法

### 第一原则 · 先设局后入人

**不要纠结主角爱吃甜还是爱吃咸** · 先想"**这个局怎么布才精妙**"。

整个故事中，各种事件之间的逻辑、因果关系，**牵一发而动全身**，这样主角才能靠着一步步的行动，解决这个巨大的难题。

### 第二原则 · 由外向内

```
外部危机 / 谜题  →  事件结构  →  事件因果链  →  填入功能性角色
                                                    ↓
                                                 角色因事件而存在
```

### 第三原则 · 人物是棋子

**原始设计的事件不可反转**（提高故事困境，增加压力）· 只有特殊的主角，进行的关键的选择，才将这个结局**引向另外的可能性**。

→ 主角"棋子"属性 = 他的人物特质必须是**破解谜题所需**的，而不是"魅力光环"。

## 三步实操（LLM 提示词指引）

### 步骤 1 · 高概念（设计无法拒绝的核心钩子）

设计一个**核心危机或核心谜题**，要求满足：

| 维度 | 要求 | 示例 |
|---|---|---|
| **影响范围** | 不只主角，影响范围越大越好 | "全人类某天早上突然失明" |
| **不可逆** | 不能简单解决（拨电话 / 找人帮忙）| "陨石撞地球还有 24 小时" |
| **观众一句话能描述** | 高概念测试 · 一句话讲清楚 | "凶手在密室里" / "时间循环不能逃脱" |
| **逻辑可破解** | 不是纯魔法 · 必须有内在规则 | "凶手必须懂第三种语言" |

→ LLM 生成时**先生成 3 个候选**，让用户选最 hook。

### 步骤 2 · 搭结构（事件因果图）

像工程师画图纸一样，设计**事件之间的因果关系**：

```
起点事件 → 触发条件 1 → 子事件 A
                       └→ 子事件 B → 中点逆转 → 终极抉择
                                              └→ 结局
```

每个事件回答 4 问：
1. **起因**：什么让这件事发生？（前置事件）
2. **过程**：当事人做了什么 / 没做什么？
3. **结果**：本事件对全局的不可逆改变？
4. **下一步**：本事件解锁了哪些后续事件？阻断了哪些？

→ LLM 生成大纲时**列因果图**而非线性时间表。

### 步骤 3 · 填角色（功能性角色）

为了让起始事件按设计推进，**反推需要什么样的功能性角色**：

| 角色功能 | 必须具备的特质 | 示例 |
|---|---|---|
| 解谜者 | 智商高 / 专业知识 / 观察细致 | 侦探 / 学者 / 黑客 |
| 推动者 | 行动力 / 不畏风险 / 关键人脉 | 战士 / 老兵 / 黑帮人物 |
| 信息携带者 | 知道关键真相 / 但不愿轻易开口 | 老者 / 受害者家属 / 罪犯 |
| 反派 | 与主角对应的镜像 / 同等智商 | 莫里亚蒂 / 主角的导师 |
| 破坏者 | 不知情但搅局 | 警察 / 媒体 / 路人甲 |

**关键**：填角色时**不需要先想他的童年 / 性格 / 弱点** · 只需问"他怎么完成功能"。性格在写作中**自然涌现**。

## 注入指引（fili-web 内部用）

- `novel.1.1`（世界观）：强调"内在规则"必须可破解 · 禁止纯魔法 deus ex machina
- `novel.1.2`（角色 bible）：每个角色必填"功能定位"+"破解力"
- `novel.2.1`（分卷规划）：每卷必须解锁 1 个核心谜题 + 抛出 1 个新谜题
- `novel.2.2`（单卷分章）：每章必须有"信息揭示" 或 "事件推进"
- `novel.3.1`（章节草稿）：每章结尾必有 1 个未解之谜（cliffhanger）
- `novel.3.2`（章节润色）：检查事件因果链是否成立

## 检验清单（dogfood 时人工抽检）

- [ ] 第 1 章 5000 字内，**核心危机已抛出**（不能拖到第 3 章）
- [ ] 中点（卷的 1/2 处）必有**逆转**（揭示真相的一部分 + 引出更大谜题）
- [ ] 终局必须**逻辑可推演**（读者回看应能"啊原来是这样"，不能纯靠主角脑洞）
- [ ] 反派的智商 / 资源 ≥ 主角（否则破解过程不刺激）
- [ ] 至少有 2 处"伪线索"（误导读者的合理误判）

## 范例 · 一句话激活公式

```
在 { 世界观 } 里，{ 起始危机 } 突然发生，
谁也无法解释，主角 { 功能定位 } 卷入其中。
他必须借助 { 解谜资源 } 在 { 时限 } 内
找出 { 真相 / 凶手 / 出路 }，否则 { 不可承受代价 }。
```

把这段填空给 LLM · 事件骨架自动出来。

## 与"信息差 / 预期管理 / 节奏控制"3 大理论的关系

事件驱动法 = "**信息差是引擎**（读者比主角少 / 主角比读者少）+ **预期管理靠节点**（每章一个反转）+ **节奏控制靠刺激密度**（推理片每章必有发现 / 灾难片每章必有伤亡）"。

```
事件驱动 = 信息差 × 预期管理 × 节奏控制 的事件坐标系
```

→ 选了事件驱动 = 三大理论自动从"事件视角"展开。
