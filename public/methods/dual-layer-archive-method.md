# 双层存档方法 · 数据库层 + 读者层 · 交叉验证抓硬伤

> **来源**：self-evolving-auditor v4.0 概念提取（重写为通用叙事方法论 · 去除审核工具特定的 markdown 文件结构）。
> **定位**：character 层 · **跨章节追踪强化型模块**（与 character-810-blueprint / character-bible / characterStates 强协同）。
> **核心命题**：长篇小说"人物崩塌 / 数据矛盾"两大硬伤的根源 · 是只有"事实记录"没有"理解记录"。**双层存档** · 让每个事件同时记录"是什么"和"为什么" · 用交叉验证抓出潜在 bug。
> **核心价值**：(1) 双层心智模式（数据库 + 读者）；(2) 4 类交叉验证（DB→DB / DB→Reader / Reader→Reader / Reader→New）；(3) 填补 fili-web "读者层"盲区。

---

## 适用边界

✅ **强推荐启用**：
- 长篇小说（>10 万字 · 易出现矛盾）
- 多角色复杂剧情（>5 个主要角色）
- 含数值系统的题材（玄幻 / 仙侠 / 系统流 · 灵石 / 等级 / 属性等）
- 跨章节追踪需求高的项目

⚠ **可选启用**：
- 中长篇（部分采用 · 主要看角色复杂度）

❌ **不要启用**：
- 短篇 / 单元剧（追踪成本 > 收益）
- 散文 / 抒情向（无数据系统）

## 核心心法 · 事实 ≠ 理解

### 痛点

```
长篇小说最常见 bug：
  Bug A：第 5 章主角有 250 灵石 · 第 30 章只剩 10 块 → 数据矛盾
  Bug B：前 20 章主角谨慎 · 第 21 章突然冒险赌博 → 人物崩塌

→ Bug A 是"数据库层"问题（事实不一致）
→ Bug B 是"读者层"问题（理解不一致）

单层存档只能抓 A · 抓不了 B
```

### 解决方案

```
双层存档 = 两层并行追踪
        ├─ 数据库层（事实）：是什么
        └─ 读者层（理解）：为什么

每章同时录入两层 · 交叉验证

→ 数据库层抓"数值矛盾"
→ 读者层抓"人物崩塌 + 动机不合理"
→ 两层互相验证抓"事实与理解的脱节"
```

## 双层存档详解 ★ 核心实操

### 层级 1 · 数据库层（"是什么"）

#### 思维模式

**数据思维**：客观、可验证、可量化。

#### 记录什么

| 类型 | 内容 |
|---|---|
| **数值** | 灵石 / 等级 / 属性 / 资金 / 武器伤害 |
| **状态** | 存活 / 死亡 / 失踪 / 受伤 / 被捕 |
| **位置** | 角色当前在哪 / 谁和谁在一起 |
| **时间线** | 故事内的时间推进 / 关键事件日期 |
| **物品** | 谁有什么物品 / 物品的传递 |

#### 写法 · 用表格 + 编号

```
| 项目      | 变动  | 新值      | 依据                    |
|----------|------|----------|------------------------|
| 张三灵石  | +100 | 100      | ch001: "系统发放 100 灵石" |
| 张三等级  | 不变  | 炼气一层  | —                       |
| 李四      | 死亡  | —        | ch015: "李四从悬崖坠落"   |
```

→ 每条记录必须**带"依据"**（章节 + 引用原文）。

#### 解决什么 bug

```
✅ 数据矛盾：第 N 章灵石数 ≠ 累积变动
✅ 时间线乱：A 事件早于 B 但描述反了
✅ 状态错乱：第 30 章 NPC 还活着但其实第 15 章已死
```

---

### 层级 2 · 读者层（"为什么"）

#### 思维模式

**读者思维**：主观、解释性、关注因果。

#### 记录什么

```
我看到的（What I saw）：
  100-200 字 · 像跟朋友复述剧情那样
  不要用数据库语气

我知道的（What I know）：
  每条一句话
  写"我现在知道了什么"
  不是复述原文 · 是提炼和理解

我在想的（What I'm wondering）：
  读者自然会产生的疑问
  对后续剧情的预测
  觉得哪里"不太对劲"的直觉

关键理解（Cause / Motive / Relation）：★ 最关键
  为什么这个角色做了这件事
  这个事件背后的逻辑
  人物之间的关系变化
  → 这一条是读者层的核心价值
  → 数据库记录不了的东西
```

#### 写法示例

```markdown
### 第 5 章

#### 📖 我看到的
张三在街上遇到混混 · 没有反抗 · 而是用 50 灵石买通了他们离开。
之后偷偷跟踪混混回到他们的窝点 · 记下了位置。

#### 🧠 我知道的
- 张三性格谨慎 · 不会无谓冒险（用钱解决而非硬碰）
- 张三有"长期布局"思维（跟踪而非立刻报复）
- 街上混混势力对主角是中等威胁

#### 🔍 我在想的
- 张三为什么不直接打？是实力不够还是怕暴露？
- 跟踪到窝点要做什么？复仇 / 利用 / 还是其他？
- 这 50 灵石的支出会不会影响后续修炼？

#### 💡 关键理解
- 张三的"谨慎"不是怯懦 · 是有策略（伏笔：他在布局）
- 张三与混混的关系：表面妥协 · 暗中报复
- 这一章为后续"张三智斗"剧情铺垫
```

#### 解决什么 bug

```
✅ 人物崩塌：性格设定 vs 章节行为 矛盾
✅ 动机不合理：角色突然做出违背性格的事
✅ 关系断裂：A 与 B 的关系变化没有合理铺垫
✅ 直觉异常：读者觉得"不对劲" 但说不出哪里
```

## 4 类交叉验证 ★ 抓硬伤的核心

### 验证 1 · 数据库 → 数据库（DB-DB）

```
检查事项：
  - 数值是否前后一致？
  - 人物状态是否矛盾？
  - 时间线是否连贯？
  - 物品归属是否清楚？

示例：
  ❌ 第 5 章张三 250 灵石 · 第 8 章无变动记录但第 10 章只剩 10 块
  → 触发"数据矛盾"警告 · 中间章节缺失变动记录
```

### 验证 2 · 数据库 → 读者层（DB-Reader）

```
方向 A：数据库的事实 · 读者层有没有理解？
  例：数据库记 "张三获得 100 灵石" · 但读者层没提
  → 可能：读者忽略了 · 或剧情不重要 · 或 LLM 漏掉
  → 决议：人工确认是否要补充读者层

方向 B：读者层的理解 · 数据库能不能支撑？
  例：读者层写 "张三很谨慎" · 但数据库没有相关行为记录
  → 触发"理解无依据"警告
  → 决议：要么补数据库依据 · 要么删读者层判断
```

### 验证 3 · 读者层 → 读者层（Reader-Reader）

```
新章节的理解 · 和之前的理解是否矛盾？

示例 A · 正常成长：
  第 3 章："张三信任师父"
  第 15 章："张三开始怀疑师父"
  → 这是正常的角色成长 · 但需要确认是否有铺垫

示例 B · 异常崩塌：
  第 3 章："张三性格谨慎"
  第 4 章："张三冲动赌博输光积蓄"
  → 触发"人物崩塌"警告 · 没有过渡章节铺垫

新章节是否回答了之前的疑问？
  第 1 章："骸骨说海里怎么会有这种东西？"
  第 5 章揭晓答案 → 更新疑问状态为"已回答"
```

### 验证 4 · 读者层 → 新章节（最关键 ★）

```
新章节中角色的行为 · 和读者层记录的性格/动机是否一致？

示例：
  读者层（前 20 章累积）：张三性格谨慎 · 不会冒险
  新章节（第 21 章）：张三主动挑战比自己强的敌人
  
  审核：
    □ 是否有充分的动机铺垫？
    □ 章节内是否解释了为什么打破谨慎？
    □ 是否有外部压力（限期 / 威胁 / 道德绑架）？

  如果都没有 → 触发"人物崩塌"严重警告
  如果有 → 通过 · 但需更新读者层："张三在 X 条件下会冒险"
```

## 4 类交叉验证 · 速查矩阵

| # | 验证类型 | 抓什么 | 严重度 | 频率 |
|:---:|---|---|:---:|:---:|
| 1 | DB → DB | 数值/状态/时间矛盾 | 🟡 中 | 每章 |
| 2 | DB → Reader | 事实与理解脱节 | 🟡 中 | 每章 |
| 3 | Reader → Reader | 理解前后不一致 | 🟠 中高 | 每 5 章 |
| 4 | Reader → New | **人物崩塌**（最严重）| 🔴 高 | 每章 |

## 实战操作流程

### 单章录入流程

```
新章节产出
    ↓
Step 1 · 数据库层录入
  □ 更新人物状态（出场 / 死亡 / 状态变化）
  □ 记录数值变动（灵石 / 等级 / 资源）
  □ 更新时间线
  □ 更新钩子 / 伏笔状态
    ↓
Step 2 · 读者层录入
  □ 写"我看到的"（100-200 字复述）
  □ 写"我知道的"（提炼理解）
  □ 写"我在想的"（疑问 / 预测）
  □ 写"关键理解"（因果 / 动机 / 关系）★
    ↓
Step 3 · 4 类交叉验证
  □ DB → DB
  □ DB → Reader
  □ Reader → Reader（与之前对比）
  □ Reader → New（与累积性格对比）
    ↓
Step 4 · 输出连续性报告
  □ 通过项
  □ 警告项
  □ 错误项（人物崩塌 / 数据矛盾 / 逻辑硬伤）
```

### 输出格式

```markdown
# 连续性检查报告 · 第 X 章

## ✅ 通过
- 数据库：人物状态一致
- 数据库：时间线连贯
- 读者层：角色动机合理

## ⚠️ 警告
### 数据层警告
- [数值问题描述]

### 读者层警告
- [理解 / 动机 / 逻辑问题描述]

### 交叉验证警告
- 数据库说 X · 但读者理解是 Y · 请确认

## ❌ 错误
### 数据不一致
- [严重] 具体描述 + 依据

### 人物崩塌（最严重）
- [严重] 具体描述 + 依据（引用读者层的性格记录）

### 逻辑硬伤
- [严重] 具体描述 + 依据
```

## 实战检验法

### 写完每章后 · 4 项自检

#### 自检 1 · 数据库层完整性

- [ ] **每个数值变动**都有依据（章节 + 原文引用）？
- [ ] **每个状态变化**都有依据？
- [ ] 时间线**没有断层**？

#### 自检 2 · 读者层完整性

- [ ] "我看到的" 100-200 字 · 不是数据库语气？
- [ ] "我知道的" 是**提炼**不是复述？
- [ ] "我在想的" 体现**真实疑问**（不是 AI 套路）？
- [ ] "关键理解" 写出了**因果 / 动机 / 关系**？

#### 自检 3 · 交叉验证全跑

- [ ] DB → DB 通过？
- [ ] DB → Reader 通过？
- [ ] Reader → Reader 通过（无前后矛盾）？
- [ ] Reader → New 通过（角色行为 vs 累积性格）？

#### 自检 4 · 报告完整

- [ ] 输出**连续性检查报告**？
- [ ] 错误项**全部有依据**（引用具体章节段落）？
- [ ] 警告项**给出建议**（怎么改）？

## 常见错误

```
❌ 只记数据库 · 不写读者层（与无效 90% 价值）
❌ 读者层写成"复述原文"（应是提炼理解）
❌ 关键理解写"主角很厉害"（空洞 · 应写因果 / 动机）
❌ 不做交叉验证（双层存档变成"双倍数据库"）
❌ 数据库变动没依据（无法追溯 · 不能验证）
❌ 读者层每章都写"我没看出什么"（懒惰 · 失去意义）
❌ 验证 4 通过但没有累积更新（性格记录过时 · 后续验证失效）
```
