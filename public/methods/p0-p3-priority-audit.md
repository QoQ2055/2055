# P0-P3 优先级分级审核 · 阻断阈值 + 诊断信号

> **来源**：网文审核官 v5.0 概念提取（重写为通用方法论 · 去除"卫无漏"人设和工作流程）。
> **定位**：craft 层 · **审核分级决策型模块**（与 ScoreCard 7 维评分互补 · ScoreCard 给"分数" · 本模块给"阻断决策"）。
> **核心命题**：fili-web 现有 ScoreCard 是"7 维 0-10 评分" · 但**缺"阻断阈值"**——什么问题必须改、什么问题建议改、什么问题可以放？P0-P3 框架直接对接业务决策。
> **核心价值**：(1) 4 级优先级（P0 致命 / P1 重要 / P2 优化 / P3 可选）；(2) 每级配诊断信号 + 修正方向；(3) "P0 不改不能过"硬律与现有 pipeline 对接。

---

## 适用边界

✅ **强推荐启用**：
- 商业网文连载（番茄 / 起点 / 七猫等）
- 平台投稿前最终审核
- 多轮润色场景（决定哪些必改）

⚠ **可选启用**：
- 散文 / 实验性作品（部分采用 P0 红线）

❌ **不要启用**：
- 个人写作不投稿（无平台审核需求）
- 短篇 / 单元剧（P0/P1 风险低）

---

## 核心心法 · 评分 ≠ 决策

### 痛点

```
ScoreCard 给出：节奏 7/10 · 爽点 6/10 · 逻辑 8/10 · ...

但用户问：
  "哪个必须改？哪个建议改？哪个可以不改？"
  → 评分回答不了

→ 评分是"质量度量" · 但用户需要"行动决策"
→ P0-P3 = 行动决策框架
```

### 解决方案

```
P0-P3 = 4 级优先级 + 阻断阈值

每个 ScoreCard 维度问题 · 都映射到 P0-P3 中某一级：
  P0 致命 → 阻断（不改不能投稿）
  P1 重要 → 必改（影响整体质量）
  P2 优化 → 建议改（提升空间）
  P3 可选 → 可以放（精雕细琢）

→ "P0 不改不能过"是硬律
→ "P3 是锦上添花"是软律
```

---

## P0-P3 4 级详解 ★ 核心实操

### P0 级 · 致命（必须立即修改）★ 阻断

#### 触发即阻断

| 类型 | 说明 | 规避方式 |
|---|---|---|
| **政治敏感** | 涉及时事政治 / 政府机构 / 领导人 | 全部虚构 · 架空时空 |
| **封建迷信** | 过度宣扬鬼神 / 风水 / 宿命 | 强调虚构世界观 · 不暗示现实 |
| **涉黄低俗** | 露骨性描写 / 擦边内容 | 改为搞笑暧昧 / 情感升温 |
| **AI 生成痕迹严重** | 高频 AI 用词 / 模板句式 / 无人味 | 去 AI 化改写（参 anti-ai-flavor / ai-flavor-detection-rules）|

#### 影响

```
P0 = 投稿被拒 / 账号被封 / 内容被删
→ 商业风险最高
→ 必改 · 不能商量
→ 不改不能进下一阶段
```

---

### P1 级 · 重要（必须修改）

#### 类型清单

| 类型 | 说明 | 诊断信号 |
|---|---|---|
| **方向偏离** | 章节未体现核心卖点 / 踩了雷区 | 核心卖点 < 1 次/章 |
| **大纲偏离** | 核心事件匹配度 < 80% | 核心事件缺失或被替换 |
| **逻辑 bug** | 情节前后矛盾 | 数值 / 状态 / 因果不一致 |
| **人设崩塌** | 行为违背既定性格 | 性格突变 + 0 铺垫 |
| **战力矛盾** | 战力忽高忽低 | 打斗前后实力对比断裂 |
| **信息突兀** | 角色知道的信息无来源 | 突然知道 + 无揭露段 |

#### 影响

```
P1 = 读者直接弃书 / 评论区差评
→ 影响完读率 + 留存率
→ 必改 · 但允许多轮迭代
```

---

### P2 级 · 优化（建议修改）

#### 类型清单

| 类型 | 说明 | 诊断信号 |
|---|---|---|
| **节奏问题** | 铺垫过长 / 节奏拖沓 | 3 章无进展 |
| **钩子不够** | 章末钩子太弱 | 读者可能流失（追读率掉）|
| **爽点密度低** | 冲突不够密集 | 平淡如水 |
| **代入感差** | 读者无法共鸣 | 跳脱 · 距离感 |

#### 影响

```
P2 = 读者觉得"还行但不爽"
→ 影响推荐率 + 互动率
→ 建议改 · 但不阻塞投稿
```

---

### P3 级 · 可选（建议考虑）

#### 类型清单

| 类型 | 说明 | 操作 |
|---|---|---|
| **伏笔未回收** | 埋设但未规划回收 | 标注预期回收章节 |
| **文笔优化** | 文字可以更精炼 | 精瘦改写 |
| **细节打磨** | 场景可以更丰富 | 五感描写补充 |

#### 影响

```
P3 = 让作品从 80 分到 90 分
→ 锦上添花
→ 时间允许就改 · 不允许就放
```

## P0-P3 速查矩阵

| 级别 | 严重度 | 阻断 | 必改？ | 影响 |
|:---:|---|:---:|---|---|
| **P0** | 致命 | 🔴 阻断 | 必改 | 投稿被拒 / 账号风险 |
| **P1** | 重要 | 🟠 必改 | 必改 | 读者弃书 / 差评 |
| **P2** | 优化 | 🟡 建议 | 建议 | 推荐率下降 |
| **P3** | 可选 | 🟢 可改 | 可放 | 锦上添花 |

## P0-P3 vs ScoreCard 7 维 · 对接关系

```
ScoreCard 7 维（fili-web 现有）：
  genre / method / kbRedline / craft / r1Align / userKbStyle / transition

P0-P3 4 级（本模块）：
  致命 / 重要 / 优化 / 可选

对接逻辑：
  ScoreCard 维度问题（任何维度）+ 对照 P0-P3 类型 → 得出优先级

例：
  ScoreCard kbRedline 维度 4/10 + 含"政治敏感"内容 → P0 致命
  ScoreCard craft 维度 6/10 + 章末钩子弱 → P2 优化
  ScoreCard transition 维度 9/10 + 文字可精炼 → P3 可选

→ ScoreCard = 评分（量）
→ P0-P3 = 决策（行动）
→ 两者结合 = 完整审核闭环
```

## 审核执行流程 · 与 fili-web pipeline 对接

```
N3.2 章节润色完成
    ↓
ScoreCard 跑 7 维评分
    ↓
跑 P0-P3 分级审核（本模块作为方法论注入）
    ↓
P0 任一项命中 → 🔴 阻断 · 必改后才能继续
P1 任一项命中 → 🟠 警告 · 强烈建议改
P2 任一项命中 → 🟡 提示 · 优化建议
P3 任一项命中 → 🟢 可选 · 时间允许再改
    ↓
用户决策（改 / 放）
    ↓
若有 P0 改 → 回到 N3.2 重新润色
若无 P0 → 进入 N3.3 章节衔接评分（gap-c）
```

## 实战检验法

### 单章审核 · 4 级自检

#### P0 自检（致命）

- [ ] 政治敏感 0 项？
- [ ] 封建迷信 0 项？
- [ ] 涉黄低俗 0 项？
- [ ] AI 生成痕迹严重 0 项？

#### P1 自检（重要）

- [ ] 方向 / 大纲 / 逻辑 / 人设 / 战力 / 信息 6 类 0 项？

#### P2 自检（优化）

- [ ] 节奏 / 钩子 / 爽点 / 代入感 4 类问题数 ≤ 2 项？

#### P3 自检（可选）

- [ ] 伏笔 / 文笔 / 细节 3 类已规划处理？

### 决策树

```
P0 ≥ 1？
  └─ 是 → 🔴 阻断 · 必改后重审

P1 ≥ 3？
  └─ 是 → 🟠 必改 · 不允许进下一章

P2 ≥ 5？
  └─ 是 → 🟡 强烈建议改 · 影响推荐量

P3 ≥ 10？
  └─ 是 → 🟢 时间允许就改 · 不强求
```

## 常见错误

```
❌ P0 一项命中还允许继续（违反阻断硬律）
❌ P1 全部当成 P3（误判严重度）
❌ P3 全部当成 P0（过度严苛 · 创作疲劳）
❌ 只看分数不看 P 级（评分 vs 决策混淆）
❌ P 级判断不引用诊断信号（凭感觉）
❌ 没有修改建议（光指错不指改）
❌ 同一问题在多个 P 级被记录（重复计数）
```

- [ ] **每章润色后**跑 P0-P3 审核

- [ ] **P1 命中 → 必改后才进下一章**
