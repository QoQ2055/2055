## 一、ATU 锚定提示模板 AAPT

原方案提出每次章节生成的 prompt 都应包含 5 层结构化标注：

```
【元数据层】 ALMEF 编码（英雄之旅阶段 + ATU 类型 + 功能母题序列）
【情境层】 时间 / 地点 / 角色状态 / 前情提要
【任务层】 本章需完成的叙事功能
【约束层】 禁止的设定冲突 / 角色偏差 / 文风要求
【输出层】 格式规定（场景标题 / 正文 / 对话标注 / 情感节拍）
```

### 对 fili-web 的启示

当前 `compose.ts` 已实现类似分层：
- 元数据层 ≈ 方法论模块注入（提供 ATU / 英雄之旅编码）
- 情境层 ≈ 前文摘要 + MemDir 当前状态（但 fili-web 单用户无 MemDir，用节点产物链条代替）
- 任务层 ≈ 节点原生 prompt
- 约束层 ≈ 用户 KB 的 antiPattern + styleGuide
- 输出层 ≈ 节点 prompt 的输出格式要求

**差异**：fili-web 没有"元数据层的 ALMEF 编码"这一步。如果未来要做 ATU / 英雄之旅节拍跟踪，可考虑在 `ProjectContext` 加 `currentBeat: { atuCode, heroStage, fsmSequence }` 字段，由上层节点维护，下层节点读取。

## 二、三层上下文窗口管理 HCC（Hierarchical Context Control）

原方案设计的三层上下文权重：

| 层级 | 内容 | token 预算 | 权重 |
|---|---|---|---|
| 全局层 GC | 英雄之旅阶段概要 | ~200 tokens | 0.3 |
| 中观层 MC | 功能母题链 | ~1000–2000 tokens | 0.5 |
| 微观层 MiC | 前 2000–4000 字正文 | ~2000–4000 tokens | 0.8 |

### 对 fili-web 的启示

这与 Master Writer V4 的 M3（上下文卫生）+ M7（Prompt Cache 经济）思路一致，可一并纳入未来的 Hook 系统设计。关键差异是**权重概念** —— 原方案建议权重控制各层的注意力分配，但主流 LLM 并不直接支持"权重"参数，只能靠 prompt 结构引导。

**实用简化**：fili-web 当前靠节点链条天然实现分层（产物 → 下游节点只读必要摘要），比"权重"更直接。可不引入权重概念。

## 三、一致性保障三工具

原方案设计的三套工具：

### 3.1 ASEVL 向量库（ATU Supernatural Element Vector Library）

每个超自然元素编码为高维向量：
- ATU 母题编码（one-hot）
- 功能属性（攻击 / 防御 / 辅助…）
- 强度等级（1–10）
- 使用限制（次数 / 条件 / 代价）
- 叙事关联（绑定角色 / 情节）

**一致性查询操作**：
- 新生成内容前检索相关已出现元素
- 检查是否存在冲突（如"唯一物品"后续出现复制品）
- 命中冲突触发修复机制

**对 fili-web 的启示**：当前 `plot-coherence-scaffold` 方法论模块的「一致性 5 条校验」是该工具的**prompt 级实现**。真正的向量库实现属于未来架构升级范围 —— 可与 M15.2 SyncHook（章节自动提取）结合做。

### 3.2 角色声音指纹 VF（Voice Fingerprint）

追踪每个角色跨章节的语言特征：
- 句式偏好（长 / 短 / 节奏）
- 高频词汇
- 语气标记
- 称呼习惯

**对 fili-web 的启示**：用户 KB 的 `voiceCard` 类型已覆盖这一层，但当前无自动采样机制。未来可考虑在章节生成后自动提取**角色台词样本**写入项目的 voiceCard 候选池。

### 3.3 因果图 CG（Causal Graph）

节点类型：状态节点 / 事件节点 / 决策节点
边类型：因果边 / 条件边 / 时序边

**对 fili-web 的启示**：`plot-coherence-scaffold.md` 模块的"因果链硬律"是该工具的 prompt 级实现。真正的图数据结构实现属于未来架构升级范围。
