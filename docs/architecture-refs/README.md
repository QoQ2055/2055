# 架构参考 · `architecture-refs/`

本目录存放**外部 AI 写作系统的架构蓝本**，供 fili-web 未来演进时做对标。

## 与其他文档目录的区别

| 目录 | 内容 | 是否运行时可见 | 定位 |
|---|---|---|---|
| `public/prompts/` | 节点原生 prompt | ✅ | 流程节点主 prompt |
| `public/methods/` | 方法论模块 | ✅ | 项目级可叠加方法论 |
| `docs/prompt-archives/` | 待集成的完整 prompt 模板 | ❌ | 等主流程升级时挪进 `public/prompts/` |
| **`docs/architecture-refs/`**（本目录） | 外部 AI 写作系统的**完整架构蓝本** | ❌ | 架构级对标，用于未来升级决策参考 |

## 判别规则：什么归本目录？

**同时满足**：

1. 它描述的是**另一个系统**（有自己的 Agent 编排 / 记忆管理 / 权限模型 / 钩子系统…），不是单纯的写作规则或素材
2. 体量 ≥ 800 行，含多模块架构设计
3. 与 fili-web 运行环境**错位**（如基于多 Agent + 云端 + 聊天群 vs 浏览器 Dexie），不能直接集成
4. 整体思路对**未来架构升级**有参考价值，但抽取任何一小块都会丢失对标价值

## 归档文件的必要元数据

每个归档文件头部必须包含：
- 归档日期 / 原始来源 / 规模（行数 / 模块数）
- **能力对照表**：外部系统每个主要模块 vs fili-web 是否已覆盖
- **可借鉴功能点清单**：分优先级列出未来升级时可吸收的条目
- 原文件路径（指向原始位置，不复制全文，避免 git 仓库臃肿）

## 使用方式

当要对 fili-web 做架构升级时（如加 Hook 系统 / Agent 化 / 多实例协作），先扫本目录已有的对标文档，看是否有现成蓝本可借鉴，避免重复造轮子。
