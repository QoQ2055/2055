## 一、为什么 cineforge 需要题材锚点系统

### 1.1 当前体系的盲区

cineforge 现有 24 个方法模块**主要是叙事结构方法**：
- 结构层：Save the Cat 15 拍 / Truby 22 步 / Harmon 故事圆圈 / 雪花法 / 起承转结 / ...
- 角色层：MBTI / 三要素方法 / ...
- 工艺层：anti-ai-flavor / 三密度 / 网文节奏包 / 反 AI / ...

**但缺少"题材是什么"的硬约束**：
- 用户写"玄幻"和"都市"应有完全不同的世界观规则、词汇库、爽点配方
- 用户写"修仙"时**必须避免**科技元素混入；写"科幻"时**必须避免**魔法/修仙元素
- 不同题材的**默认字数 / 段落长度 / 对话比例**差异显著（言情对话 40% vs 科幻 22%）

### 1.2 双轴模型

```
       ┌──────────────────────┐
       │   叙事结构（怎么写）  │  ← cineforge 现有 24 模块
       │                      │
       │   Save the Cat       │
       │   Truby 22           │
       │   雪花法             │
       │   ...                │
       └──────────────────────┘
                  ×
       ┌──────────────────────┐
       │   题材锚点（写什么）  │  ← 本规范（待落地）
       │                      │
       │   玄幻 / 仙侠 / 都市  │
       │   科幻 / 武侠 / 言情  │
       │   ...                │
       └──────────────────────┘
                 = 完整创作约束
```

## 二、12 字段标准化 Schema

```ts
type Genre =
  | '玄幻' | '仙侠' | '灵异' | '都市' | '科幻'
  | '奇幻' | '历史' | '游戏' | '武侠' | '悬疑'
  | '言情' | '轻小说' | '军事' | '短篇爽文' | '无限流'
  | '末日求生' | '恐怖' | '古言' | '现实' | '体育'
  | '同人' | '种田' | '系统流' | '穿越';

type NarrativePerspective = '第一人称' | '第三人称限知' | '第三人称全知';

interface GenreAnchor {
  id: Genre;
  // 1. 题材锚点：覆盖范围 + 子类型
  genreAnchor: string;
  // 2. 世界观规则：力量体系 / 冲突来源 / 主角优势的硬规则
  worldRules: string;
  // 3. 写作风格（标签）
  writingStyle: string;
  // 4. 叙述视角
  narrativePerspective: NarrativePerspective;
  // 5. 人称运用：细粒度文法约束
  pronounUsage: string;
  // 6. 情感基调（标签）
  emotionalTone: string;
  // 7. 目标字数（章节默认）
  targetWordCount: number;
  // 8. 段落长度（默认字符数）
  paragraphLength: number;
  // 9. 对话比例（百分比）
  dialogueRatio: number;
  // 10. 节奏要求：开局→中段→高潮→结尾的节奏配方
  rhythmRequirement: string;
  // 11. 必须包含：题材必备爽点（5-7 项）
  mustInclude: string[];
  // 12. 必须避免：题材污染清单（5-8 项）
  mustAvoid: string[];
}
```

- **段长差异大**：轻小说 120 字（短句多）vs 历史 240 字（长句多）
- **对话比例差异大**：科幻/历史/仙侠 22% vs 言情/轻小说 40-45%
- **第一人称**：言情 / 轻小说 / 恐怖（强代入感）
- **第三人称全知**：仅历史

## 四、关键题材的"必须包含" + "必须避免"（核心硬约束）

> 完整列表见原文，此处摘录最具示范性的 6 个题材：

### 4.1 玄幻

- ✅ **必须包含**：境界突破 / 强者对决 / 功法修炼 / 天材地宝 / 势力争锋 / 爽点反击
- ❌ **必须避免**：现代科技 / 仙侠道韵风格混入（玄幻重战斗升级而非问道悟禅）/ 现代网络梗 / 无逻辑碾压 / 突然开挂无代价 / 过度说教 / 水字数的心理独白

### 4.2 仙侠

- ✅ **必须包含**：仙法斗法 / 道心磨砺 / 天劫渡劫 / 洞天福地 / 师徒传承 / 因果代价
- ❌ **必须避免**：现代用语 / 科技元素 / 系统面板 / 过度白话 / 破坏仙侠意境的网络梗 / 无代价的无敌挂

### 4.3 灵异

- ✅ **必须包含**：鬼怪/邪祟实体 / 诡异事件与杀人规律 / 环境渲染（日常被侵蚀）/ 线索暗示与规则解谜 / 民俗禁忌与因果报应 / 禁忌代价
- ❌ **必须避免**：科幻概念混入（模因/认知污染/信息论/语义代码）/ 克苏鲁外神/触手意象 / 赛博朋克/高科技风 / 西方宗教驱魔套路 / 修仙体系混入 / 系统面板 / 无逻辑堆砌惊吓 / 破坏氛围的搞笑段子

### 4.4 科幻

- ✅ **必须包含**：科技设定自洽 / 技术驱动的核心冲突 / 未来社会形态或文明结构 / 科学逻辑链条 / 人与技术的关系探讨 / 危机升级
- ❌ **必须避免**：魔法/修仙元素混入 / 无科学依据的超能力 / 用玄幻方式解释科技 / 随意时间旅行不讲代价 / 灵异鬼怪元素 / 过度感性抒情替代逻辑推演

### 4.5 短篇爽文（特殊设计）

**爽点设计三段式**：打脸（嘲讽 → 实力展示 → 震惊反应）/ 升级反馈即时化（获得能力 → 立刻用 → 立刻见效）/ 身份反转铺垫（前文埋"被看不起"伏笔 → 关键时刻亮身份 → 所有人后悔）

**开篇要求**：第 1 章前 500 字内必须抛出核心冲突或高潮场景，禁止大段背景交代

**结局设计**：明确的情感收尾，最后一段酣畅淋漓的满足感，可保留小开放性钩子但禁止"未完待续"式悬念

### 4.6 言情（人称运用范例）

**人称约束**：第一人称叙事；每连续 3 句以"我"开头后必须改用主角姓名开头；禁止连续 4 句以上以"我"起句；双视角交替时以姓名或场景切割明确标识

> 这是 cineforge 当前完全没有的文法层约束，对避免 AI 行文重复感非常有效

## 五、与现有方法模块的协同关系

### 5.1 不冲突 / 互补

题材锚点（写什么）和方法模块（怎么写）**正交**，应同时启用：

```
项目：网文连载《九霄剑神》
├─ 题材锚点：玄幻              ← 决定爽点配方 / 字数 / 风格 / 视角
├─ 方法模块：truby-22-steps    ← 决定叙事结构
├─ 方法模块：webfiction-pacing-pack ← 决定章节节奏
└─ 方法模块：anti-ai-flavor    ← 决定文风
```

### 5.2 潜在冲突警示

| 题材锚点 | 与现有模块潜在冲突 |
|---|---|
| 灵异 | ✅ 强烈呼应 `supernatural-webfiction-pack`（但需注意：灵异禁止"克苏鲁/触手"等元素） |
| 仙侠 | 与"系统面板"类模块冲突（仙侠必须避免系统面板） |
| 科幻 | 与"修仙"类元素冲突 |

需在 `methodModuleRecommend.ts` 增加**题材-模块兼容性矩阵**。

### 5.3 与外部平台合规呼应

- 灵异题材的**封建迷信元素**（招魂/驱鬼/算命）→ 与 `seedance-content-moderation-rules.md` 冲突
- 短篇爽文的**打脸 + 暴力**→ 注意 Seedance "暴力血腥"限制

## 六、cineforge 落地蓝图（按优先级）

### 6.1 阶段 P0：数据建模

**新建 schema** `@public/genres/<genre-id>.json`（19 个文件）：

```json
{
  "id": "玄幻",
  "displayName": "玄幻",
  "genreAnchor": "...",
  "worldRules": "...",
  "writingStyle": "热血激昂",
  "narrativePerspective": "第三人称限知",
  "pronounUsage": "...",
  "emotionalTone": "热血激昂",
  "targetWordCount": 3500,
  "paragraphLength": 190,
  "dialogueRatio": 28,
  "rhythmRequirement": "开局冲突/危机→快速升级/奇遇→强者对决与反转→结尾留悬念",
  "mustInclude": ["境界突破", "强者对决", "功法修炼", "天材地宝", "势力争锋", "爽点反击"],
  "mustAvoid": ["现代科技", "仙侠道韵风格混入", "现代网络梗", "无逻辑碾压", "..."]
}
```

新建 manifest `@public/genres/manifest.json` 索引 19 题材。

### 6.2 阶段 P1：项目元数据扩展

`@src/pipeline/types.ts` `ProjectContext` 增加：

```ts
interface ProjectContext {
  // ... existing
  genreId?: Genre;       // 关联到 genre-anchor 配置
}
```

### 6.3 阶段 P2：compose 注入

`@src/pipeline/compose.ts` 在系统 prompt 拼接时**优先注入题材锚点**（高于方法模块），形成：

```
[base system prompt]
[genre anchor 注入] ← 12 字段拼接为段落
[method modules 注入]
[user kb docs 注入]
[user message]
```

### 6.4 阶段 P3：UI

- 新建 `GenreAnchorPanel.tsx` 题材选择面板（与 `MethodModulePanel.tsx` 同级）
- 项目创建时**强制要求选择题材**（默认推荐"短篇爽文"或"都市"）
- UI 显示"必须包含" / "必须避免"两套清单作为创作指引

### 6.5 阶段 P4：题材-模块兼容性矩阵

`@src/pipeline/methodModuleRecommend.ts` 增加：

```ts
interface MethodModuleMeta {
  // ... existing
  genreCompat?: {
    recommended?: Genre[];     // 推荐组合
    incompatible?: Genre[];    // 互斥
    requireWarning?: Genre[];  // 启用时弹窗警示
  };
}
```

例如 `supernatural-webfiction-pack` 的 `recommended: ['灵异', '恐怖']` / `incompatible: ['科幻', '现实']`。

### 6.6 阶段 P5：章节生成参数自动适配

LLM 调用时根据 `genreId`：
- `targetWordCount` → `max_tokens` 上限
- `paragraphLength` → 提示词中段落长度约束
- `dialogueRatio` → 提示词中对话密度约束
- `pronounUsage` → 提示词中人称切换约束

### 6.7 阶段 P6：质量校验

章节生成后基于题材锚点自动校验：
- 是否包含"必须包含"项的至少 N 项
- 是否触犯"必须避免"项
- 字数 / 段长 / 对话比例 是否符合配置
- 形成"题材一致性评分"
