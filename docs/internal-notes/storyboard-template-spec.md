## 一、单镜 17 字段 Schema

### 1.1 字段总览（TypeScript Interface 形式）

```ts
interface StoryboardShot {
  // ===== 1. 元数据 =====
  shotNumber: number;                  // 01-24
  duration: number;                    // 秒，典型 15
  type: ShotType;                      // A/C/D/E/F
  template: TemplateId;                // T1-T15
  tier: 'LITE' | 'PRO';                // 档位
  rhythm: string;                      // 节奏一句话（如 "失重俯冲→空间擦脸→同轴锁线"）

  // ===== 2. 挂载（资源引用） =====
  mounts: {
    characters?: string[];             // @角色：xxx
    scene: string;                     // @场景：xxx
    audio?: { id: string; desc: string }[]; // @音频1/2/3
  };

  // ===== 3. 镜头几何 =====
  cameraPosition: string;              // 相机位置（含演变路径）
  cameraOrientation: string;           // 相机朝向
  characterOrientation: string;        // 角色朝向
  compositionAnchor: string;           // 构图锚点

  // ===== 4. 起落幅 =====
  openingFrame: string;                // 起幅描述
  closingFrame: string;                // 落幅描述

  // ===== 5. 连续性（核心创新） =====
  continuity: {
    inheritFrom: string;               // 承接：来自上一镜的什么
    handoverTo: string;                // 过门：交给下一镜的什么
    handoverMethod: string;            // 过门方式（动作动势硬切 / 拟音先入 / 图形匹配 / 情绪压场 / ...）
    handoverProp: string;              // 接力物（同一条冲刺线 / 蓝色尾焰 / 失败玩家海 / ...）
  };

  // ===== 6. 双版本锚 =====
  aspectAnchors: {
    portrait: string;                  // 9:16 锚点
    landscape: string;                 // 16:9 锚点
  };

  // ===== 7. 即梦提示词正文 =====
  prompt: {
    qualityDescription: string;        // S+质量描述（最长，提示词主体）
    forbiddenStatement: string;        // 强制声明（无BGM/无字幕/无UI...）
    mustShow: string[];                // 目标物 Must-Show
    qualityRoute: string;              // 画质路线
    imagingPersonality: string;        // 成像个性
    qualityFloor: string;              // 画质底线（5 句标准）
    referenceCoverageStability: string;// 参照·覆盖·稳帧
    microExpression?: string;          // 微表情（仅有人物特写时）
    e15Closure?: string;               // E15 写实闭环（仅 E 类镜头）
    nailFourLines: [string, string, string, string]; // 钉子 4 行
  };
}
```

### 1.2 字段优先级

| 字段 | 必填 | 用途 |
|---|---|---|
| 镜号 / 时长 / 类型 / 模板 | ✅ | 索引 |
| 节奏 | ✅ | 一句话总结，便于快速浏览 |
| 挂载 | ✅ | 资源引用，连接到其他系统（角色卡 / 场景库 / 音频库） |
| 相机几何（4 项） | ✅ | 视觉构图核心 |
| 起落幅 | ✅ | 镜头起止状态 |
| **连续性 4 项** | ✅ | **跨镜因果锚点（核心创新）** |
| 双版本锚 | ✅ | 多比例适配 |
| S+质量描述 | ✅ | 提示词主体（最长） |
| 强制声明 / Must-Show / 画质路线/ 个性/ 底线 | ✅ | 控制约束 |
| 钉子 4 行 | ✅ | 核心冲击力锚点 |
| 微表情 | 可选 | 人物特写时 |
| E15 闭环 | 可选 | E 类（写实闭环）镜头 |

## 四、核心概念（可反哺到现有小说模块）

### 4.1 "钉子 4 行"

每镜末尾的 4 句核心冲击力锚点。**每行一个钉子**，把镜头的"为什么值得拍"钉死。

> 示例（分镜 01）：
> 1. 纯白云海被撕开的一瞬，整座自由城像从地狱烟火里掀出来。
> 2. 高楼与全息艺伎从镜头两侧擦脸掠过，前景压迫直接成立。
> 3. 断桥不是背景，而是唯一活路，必须像钢铁长矛刺向半空黑洞。
> 4. 落幅死锁冲刺中轴，让下一镜能直接贴地冲进去。

**反哺潜力**：
- 现有 `webfiction-pacing-pack` 的"章节自检"可借鉴 → 每章末尾要求作者写"钉子 3 行"作为本章核心张力锚点
- 章末钩子（volumeEndHook）的设计可加"必须是一个具体的钉子，不是模糊的悬念"

### 4.2 "双版本锚"

每镜同时设计 9:16（竖屏 / 短视频）和 16:9（横屏 / 院线）的构图保稳点。

> 示例：
> - 9:16 = 断桥与时空门保持上下贯通，中轴不丢
> - 16:9 = 左右高楼与巨像擦脸形成包夹，中央冲刺线不偏轴

**反哺潜力**：
- 不直接适用于小说，但**多比例 / 多媒介适配**思想可作为未来"小说-短视频-院线"多形态导出的设计原则

### 4.3 "承接 · 过门 · 接力物"（**最有价值的概念**）

镜头连续性的三段式：

| 元素 | 含义 |
|---|---|
| **承接** | 本镜从上一镜继承了什么状态 / 情绪 / 物理趋势 |
| **过门** | 本镜如何把这个状态/情绪/趋势送给下一镜 |
| **过门方式** | 动作动势硬切 / 拟音先入+动势延续 / 图形匹配硬切 / 情绪压场硬切 / 速度动势硬切 / 火力动作接棒 / ... |
| **接力物** | 具体的承接介质（同一条冲刺线 / 蓝色尾焰 / 失败玩家海 / GAME OVER 红色数码碎片 / 加特林火网 / ...） |

**反哺潜力**：⭐⭐⭐ **直接对应小说的"章节衔接"问题**

- 现有 `plot-coherence-scaffold` 模块强调因果链，但**未明确"接力物"概念**
- 可考虑给 `plot-coherence-scaffold` 加一个"章节接力物"小节：每章末必须明确"传给下一章的具体载体"（一个具体的物 / 人 / 状态变化 / 情绪余压），而不是模糊的"悬念"
- 这是从 AI 视频领域回到文学领域的一个高质量复用

### 4.4 "画质底线 5 句"（即梦专用）

每镜固定附带：
> 高光保结构、暗部不死黑、中间调厚实、主体边缘稳定、介质分层清楚

**作用**：作为"质量约束的最低要求"，无论怎么发挥都不能踩破这条线。

**反哺潜力**：
- 不直接适用，但**"质量底线（hard floor）"思想**可作为 cineforge 章节生成的"5 句不可破"自检项

### 4.5 "起幅 / 落幅"（vs 节拍）

每镜有明确的**起始状态**和**终止状态**，这是镜头化思维。

**对比小说**：现有方法模块多以"节拍"思维（Save the Cat 15 拍、Truby 22 步），但**单章内部少有"起幅/落幅"明确锚点**。可作为章节大纲的扩展字段。

### 4.6 "S+质量描述" 的 4 段式提示词结构

观察样本，每镜的提示词正文遵循固定 4 段：

1. **基调声明**（"REAL_CG，软科幻赛博末日电影质感，冷峻华丽、危险压迫；FPV 无人机式高速俯冲，但..."）
2. **物理铺陈**（场景细节、空间分层、光线、介质）
3. **动作演变**（前 3 秒 → 中段 → 尾段，时间分段明确）
4. **关键锁定**（落幅必须出现什么 / 哪些元素必须保留）

**反哺潜力**：可作为 LLM 生成"沉浸式描写段落"的结构模板。

## 五、与 fili-web 现有模块的呼应

| 现有模块 | 呼应概念 | 反哺方式 |
|---|---|---|
| `plot-coherence-scaffold` | 承接·过门·接力物 | ⭐⭐⭐ 加"章节接力物"小节 |
| `webfiction-pacing-pack` | 钉子 4 行 / 起幅落幅 | ⭐⭐ 加"章末钉子 3 行"自检 |
| `three-density-review` | 画质底线 5 句 | ⭐ "质量底线"思想（章节自检不可破项） |
| `anti-ai-flavor` | "S+质量描述" 4 段式 | ⭐ 描写段落的结构骨架 |

> **不建议立即修改现有模块**。这些是潜在改进方向，应在用户明确需要时评估。

## 六、未来"分镜导出"功能的开发蓝图

### 6.1 阶段 P0：数据结构

实现 `StoryboardShot` interface（参见第一节）+ Dexie 表存储分镜数据。

### 6.2 阶段 P1：章节 → 分镜的 LLM 转换

新建 craft 层方法模块 `chapter-to-storyboard`：
- 输入：章节正文 + 项目元数据（角色 / 场景 / 风格）
- 输出：6-12 镜的 `StoryboardShot[]`
- 注入节点：新建 `novel.4`（导出层）
- 推荐 LLM：DeepSeek V4 Pro + Thinking 启用 + 纯分析模式（参见 `@docs/internal-notes/deepseek-v4-tuning-guide.md`）

### 6.3 阶段 P2：模板系统

实现 T1-T15 模板库（每个模板提供 prompt 骨架），用户在生成时可选模板偏好。

### 6.4 阶段 P3：多 AI 视频工具适配

抽象 `StoryboardShot` → 不同工具（即梦 / Runway / Pika / Sora / 可灵 / ...）的提示词适配器。

### 6.5 阶段 P4：UI

分镜卡片视图 + 双版本锚预览 + 提示词复制按钮。

### 6.6 注意事项

- **分镜功能与小说创作主流程解耦**：分镜是导出端，不应污染 `novel.1`-`novel.3` 的方法模块推荐
- 注入节点设计：新建 `novel.4` 而非复用现有节点
- 模型选择：高频镜头扩展用 V4 Flash 控成本，结构化分镜规划用 V4 Pro
