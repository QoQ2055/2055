# 内部参考手册 · 网文创作流水线规范

> **创建日期**：2026-05-06
> **来源**：从 `@docs/reference-works/tianming-platform-prompts-original.txt` 提炼
> **目的**：为 fili-web 提供完整的"拆书 → 素材 → 设计 → 创作 → 校验"6 阶段流水线参考
> **运行时状态**：❌ 内部蓝图 / 待按需落地
> **使用方式**：未来扩展 fili-web 流水线节点（`novel.x.x` 节点系统）时的参考蓝图

---

## 一、6 阶段流水线全景

```
阶段 1：拆书分析     ← 上传参考小说，提取方法论
   ↓
阶段 2：素材设计     ← 基于拆书 + 题材，生成原创三维素材
   ↓
阶段 3：规则设计     ← 5 子模块（世界观/角色/势力/位置/剧情）
   ↓
阶段 4：创作规划     ← 4 层（战略大纲/分卷/章节/蓝图）
   ↓
阶段 5：初稿生成     ← 章节正文（fili-web 已有）
   ↓
阶段 6：润色 + 校验   ← 6 大润色工具集 + 一致性校验（独立手册）
```

---

## 二、阶段 1 · 拆书分析

### 2.1 任务

从已有作品提取**可迁移的写作方法论**，覆盖世界观 / 角色 / 剧情三大维度。

### 2.2 关键创新：结构锚点位置

按位置分层注入参考章节：

| 标签 | 位置 | 分析重点 |
|---|---|---|
| `[黄金章]` | 开篇 1-3 章 | 钩子 / 人设建立 / 世界观铺垫 |
| `[结构锚点·开篇 10%]` | 全书 ~10% | 第一个冲突爆发 + 节奏升级 |
| `[结构锚点·中段 50%]` | 全书 ~50% | 中段转折 + 矛盾深化 + 节奏控制 |
| `[结构锚点·高潮 80%]` | 全书 ~80% | 高潮蓄力 + 情绪推进 + 爆发手法 |
| `[结构锚点·结尾]` | 末章 | 结局收尾 + 情感落点 |
| `[AI 精华章·xxx]` | 高能场面（基于热评/章节目录挑选） | 名场面写法技巧 |

### 2.3 输出要求

- 每字段 200-500 字深度分析
- 提炼"为什么这样写有效" + "如何在新作中复用"
- **不复述原书情节**，输出可直接作为新作创作参考的方法论
- JSON 格式输出

### 2.4 fili-web 落地建议

新建独立功能（**不**作为 craft 层方法模块）：
- 输入：参考小说 + 章节按位置标签注入
- 模型：DeepSeek V4 Pro + Thinking 启用 + 纯分析模式
- 输出：拆书分析 JSON → 存入 `userKbDocs`（type: `bookAnalysis`，新增类型）
- 与 `extractKb.ts` 的"避免复制原文"问题呼应 → 推荐**两阶段法**（参见 `@docs/internal-notes/deepseek-v4-tuning-guide.md` 六）

## 三、阶段 2 · 素材设计

### 3.1 任务

基于拆书分析 + 创作规格约束，为新小说生成**原创**的三维度素材。

### 3.2 设计要求（关键约束）

1. **最高优先级**：严格遵守"创作规格约束"（题材锚点 + 必须包含 + 必须避免）
2. **整体构思** 400-600 字 + **小说简介** 80-120 字
3. **借鉴**写作技法和叙事结构，但**故事设定必须完全原创**且严格属于目标题材
4. 素材之间必须形成**跨维度内在逻辑关联**：
   - 角色驱动力 → 嵌入世界观规则框架
   - 剧情核心冲突 → 激活角色弧光
   - 世界观势力格局 → 为剧情冲突提供结构性支撑

### 3.3 角色姓名硬规则（关键创新）

- 主角姓名只在「角色素材-主角塑造」第一行定义
- 配角姓名在「角色素材-配角设计」中定义
- 一旦定义完成，其他字段引用必须使用**已定义姓名**
- **禁止**「某配角」「另一敌人」等模糊指代
- **禁止**引入新的无名角色

→ 这一规则**直接对应 fili-web `plot-coherence-scaffold` 的章节连续性思想**。

### 3.4 fili-web 落地建议

阶段 2 在 fili-web 现有 `extractKb.ts` 基础上扩展：
- 新 KB 类型：`materialDesign`（素材设计）
- 包含 worldview / characters / plot 三个子结构
- 与现有 `worldHardSchema` / `voiceCard` 等 KB 类型整合

## 四、阶段 3 · 规则设计（5 子模块）

### 4.1 模块语义边界（核心创新）

每个模块有**明确的语义边界声明**，防止退化为氛围描写或百科介绍：

| 模块 | 语义边界 | 反面警示 |
|---|---|---|
| **世界观规则** | 底层法则与历史框架 = 不可违背的运行规则 + 因果链历史演化 | ❌ 氛围描写 / 设定堆砌；硬规则与软规则必须区分 |
| **角色规则** | 人物长期驱动力与能力边界 = 外在目标 + 内在需求 + 致命缺点 + 成长路径，闭环弧光 | ❌ 单纯属性堆砌；技能资产必须服务主线冲突 |
| **势力规则** | 组织目标 + 成员结构 + 关系网络，互相支撑体现冲突驱动力 | ❌ 百科式介绍 |
| **位置规则** | 地点叙事功能与归属结构，服务角色行动/冲突推进/世界观揭示 | ❌ 地理观光描写；历史意义与禁忌必须说明对故事的实际影响 |
| **剧情规则** | 全书结构化事件节点，含触发条件 + 参与方 + 冲突过程 + 结果影响 | ❌ 松散桥段 / 文案式简介 |

### 4.2 通用设计要求

- **长期有效**：不写一时点情绪快照、不以一次性事件替代长期规则
- 字段字数分层控制（短标签 1-12 字 / 句摘要 20-50 / 一般说明 40-120 / 描述 80-160 / 结构机制 120-260）
- 与上下文创作素材保持一致，不出现逻辑矛盾
- 独特性和记忆点，避免通用模板化

### 4.3 与 fili-web 现有方法模块的对应

| 天命 5 子模块 | fili-web 现有 | gap |
|---|---|---|
| 世界观规则 | ✅ `world-building-9-pillars` 部分覆盖 | 需增加"硬规则 vs 软规则区分"小节 |
| 角色规则 | ✅ `character-three-elements-method` / MBTI 系列 | 需增加"长期驱动力闭环"约束 |
| 势力规则 | ⚠ `systems-analysis-six` 部分覆盖（政治/军事/经济/商业/金融/魔法 6 系统） | 缺独立的势力关系网模块 |
| 位置规则 | ❌ 没有 | **建议补建**：地点叙事功能模块 |
| 剧情规则 | ⚠ `plot-coherence-scaffold` 部分覆盖 | 缺"事件节点 4 要素"格式化 |

### 4.4 fili-web 落地建议

不必新建 5 个独立模块，而是：
- 给现有相关模块**补充语义边界小节**
- 新建 1 个 craft 层模块 `location-narrative-design`（位置规则）填补缺口

## 五、阶段 4 · 创作规划（4 层）

### 5.1 4 层规划体系

```
战略大纲 (大纲名称, 不为「第N卷」格式)
   ↓ 包含卷/幕划分
分卷设计 (大纲名称形如「第N卷：xxx」)
   ↓ 阶段目标 + 章节分配总览 + 通用约束
章节规划 (章节标题非空)
   ↓ 章节主目标 + 阻力 + 关键转折 + 结尾钉子
章节蓝图 (场景标题非空)
   开场/发展/转折/结尾四段场景因果链
```

### 5.2 关键创新：上下游回扣关系

**只在上游目标已注入时**建立回扣，禁止伪造：

```
蓝图 → 优先回扣 → 章节主目标
章节 → 优先回扣 → 分卷阶段目标
分卷 → 优先回扣 → 大纲主线走向
```

若上游未提供，则**只围绕当前任务与已有上下文**保持一致，**不擅自补造未定义内容**。

### 5.3 字段字数分层

| 层 | 短字段 | 一般说明 | 描述性 | 结构总览 |
|---|---|---|---|---|
| 字数 | 10-40 / 20-60 | 50-120 | 60-140 | 120-260 |

### 5.4 fili-web 落地建议

fili-web 现有 `webfiction-pacing-pack` 已覆盖**节奏部分**，但缺整体的 4 层规划体系。建议：
- 新建 `pipeline/types.ts` 中的层级类型 `OutlineLevel = 'strategic' | 'volume' | 'chapter' | 'blueprint'`
- 新建 craft 层方法模块 `four-level-outline`（4 层规划方法论）
- 节点系统增加 `novel.1.x` 子节点对应 4 层

## 六、阶段 5 · 初稿生成

### 6.1 7 条硬约束

```
1. 规格至上：创作规格约束最高优先级，冲突时以创作规格为准
2. 设定保护：绝对遵循已有世界观/力量体系/角色性格设定
3. 剧情一致：与前文情节/角色关系/伏笔走向保持一致
4. 纯正文输出：禁止 AI 过渡语
5. 禁止情节重置：从上一章结尾状态直接向前推进
6. 禁止段落复读：每段必须推进新内容
7. 禁止原地打转：每个场景必须产生至少一项实质推进
   （行动结果/信息揭示/关系变化/冲突升级）
```

### 6.2 fili-web 印证

约束 5-7 与 fili-web `anti-ai-flavor` 模块的"反 AI 文风"思想完全一致 → **印证现有方向正确**。

可考虑将这 7 条提升到 `compose.ts` 的**全局硬约束层**（不依赖具体方法模块），作为所有章节生成的最低标准。

## 七、阶段 6 · 一致性校验

### 7.1 任务

对章节正文进行多维度校验，覆盖：世界观 / 角色 / 势力 / 地点 / 剧情 / 大纲 / 蓝图 / 分卷设计 / 章节规划 / 文风。

### 7.2 校验原则

- 严格以"提供的设定数据"为唯一权威来源
- 区分**硬伤**（明确矛盾）→ 失败 / **软伤**（风格偏离）→ 警告
- 每条规则必须给出明确结论：通过 / 警告 / 失败 / 未校验
- 问题描述具体到原文位置或段落

### 7.3 输出格式

```ts
interface CheckResult {
  moduleResults: {
    moduleId: string;
    rules: {
      ruleId: string;
      verdict: 'pass' | 'warning' | 'fail' | 'not_checked';
      problem?: string;       // 具体到原文
      suggestion?: string;    // 修复建议
    }[];
  }[];
}
```

### 7.4 fili-web 落地建议

fili-web 现有 `ChapterFeedback` 系统接收用户反馈，可扩展为：
- **自动校验**（LLM-as-judge 模式）：基于项目设定数据自动跑全章节扫描
- **混合校验**：自动校验 + 用户反馈补充
- 校验结果存入 Dexie 新表 `chapterChecks`
- UI 显示"硬伤"红色 / "软伤"黄色 / "通过"绿色 标签
