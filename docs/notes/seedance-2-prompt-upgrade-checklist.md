## §1 · 6 大升级方向（v1.x → v2.0）

### 方向 1 · @素材引用（最核心新特性）

```
v1.x：长描述
  "穿白色长袖衬衫黑色西装裤的男性，带金边眼镜，提着深棕色公文包，
   在玻璃幕墙办公楼前的人行道上行走..."

v2.0：@素材引用
  @人物-林深 在 @场景-办公室门口 提着 @道具-公文包

原则：
  ├─ 穿插在描述中（不堆末尾）
  ├─ 命名格式：@类型-名字
  └─ 类型：@人物 / @场景 / @道具 / @音效 / @镜头
```

### 方向 2 · 时间分段格式（视频时长强制）

```
v1.x：一段长描述（无时间锚点）

v2.0：时间分段
  0-3秒：[启动] xxx
  3-6秒：[发展] xxx
  6-9秒：[高潮] xxx
  9-12秒：[落版] xxx

约束：
  ├─ 每镜 4-15 秒
  ├─ 总和 = 剧本时长（±10 秒）
  └─ 段标签格式：[标签] 描述
```

### 方向 3 · 双锚点【场景】+【承接】（视频连贯关键）

```
开头【场景】：
  ✅ 【场景：办公室·黄昏·暖光】
  含：地点 / 时间 / 光线 / 氛围

第 2 镜起【承接】：
  ✅ 【承接：上一帧 林深背对镜头·手伸向门把】
  含：人物位置 / 动作状态 / 摄像机角度

作用：
  ├─ 防止"换镜后人物瞬移"bug
  ├─ 防止"光线突变"bug
  └─ 让视频流畅过渡
```

### 方向 4 ·【对话："xxx"】格式（v2.0 强制要求）

```
v1.x：直白叙述
  林深说"你终于来了"

v2.0：明确格式
  林深转身【对话："你终于来了"】

作用：
  ├─ 让 AI 明确"哪部分是台词"（避免读出旁白）
  ├─ 让 AI 自动配口型
  └─ 让字幕/配音工具直接提取
```

### 方向 5 · 末尾固定 suffix（防崩防水印 · 必加）

```
每个 prompt 末尾必须追加：

（不生成字幕、4K高清、动作协调、电影级、画面不出现崩坏、
  人物场景和道具保持一致性、避免模糊低画质面部变形多余手指水印）

涵盖 9 项防崩：
  1. 不生成字幕
  2. 4K 高清
  3. 动作协调
  4. 电影级
  5. 画面不出现崩坏
  6. 人物场景和道具保持一致性
  7. 避免模糊
  8. 避免低画质 / 面部变形 / 多余手指
  9. 避免水印
```

### 方向 6 · 字数控制 100-200 字 / 镜

```
理由：
  ├─ token 浪费 ↓ · 模型推理稳定 ↑
  ├─ 过长 prompt 容易触发 AI"忽略前半部分"bug
  ├─ 过短 prompt 信息不足 · 生成质量低
  └─ 100-200 字 = 经验最优区间
```

## §2 · 8 项 prompt 自检 checklist

```
每个 v2.0 prompt 写完后必检：

□ [1] 用 @素材名 替代了长形容词描述？
□ [2] 时间分段（0-3s / 3-6s / ...）是否齐全？
□ [3] 开头有【场景：xxx】？
□ [4] 第 2 镜起有【承接：xxx】？
□ [5] 对话用【对话："xxx"】格式？
□ [6] 末尾加固定 suffix？
□ [7] 字数 100-200？
□ [8] 总时长 = 剧本时长（±10s）？

→ 8 项全过 = v2.0 合规
→ 缺 ≥ 2 项 = 视频生成质量风险高
```

## §3 · fili-web prompt vs Seedance 2.0 prompt 对照

```
fili-web 是小说创作工具 · Seedance 2.0 是视频生成工具。
两者都用 LLM · 但 prompt 工程目标不同。
但部分原则可类比：
```

| Seedance 2.0 | fili-web 对应 | 重叠度 | 备注 |
|---|---|:---:|---|
| @素材引用 | ProjectContext + artifacts 注入 | 80% | fili-web 用变量替换（{{title}} / {{ctx.genre}}）· 但不显式 @类型-名字 命名 |
| 时间分段 0-3s / 3-6s | 章节分段（按章 / 卷 / 段）| 50% | 颗粒度不同（秒 vs 章）· 但思路一致 |
| 双锚点【场景】+【承接】| gap-c 章节衔接评分（"承接"维度）| 70% | gap-c 已有 transition 维度 · 但未显式"承接锚点" |
| 【对话："xxx"】| N3.1/N3.2 已要求中文双引号「」 | 90% | fili-web 用「」· Seedance 用 ASCII 引号 · 思路一致 |
| 末尾固定 suffix | fili-web 各 prompt 已有 suffix | 80% | fili-web suffix 偏文学性约束 · Seedance 偏画质防崩 |
| 字数 100-200 | fili-web 各 prompt 字数更精细控制 | 90% | fili-web 按 chapter-words 计算 |

**平均重叠 ~77%** → fili-web 已隐式遵循类似原则。

## §4 · fili-web 可借鉴升级方向

```
基于 Seedance 2.0 升级思路 · fili-web 未来可考虑的 prompt 优化：
（这些是建议 · 不是 todo）
```

### 借鉴 1 · 显式素材引用语法

```
现状：fili-web prompt 用 {{title}} / {{ctx.genre}} 等
建议：可考虑 @人物-名字 / @场景-名字 / @设定-名字 类语法
价值：让 LLM 更明确"这个变量代表什么类型"
风险：低（仅 prompt 内部约定）
```

### 借鉴 2 · 显式承接锚点

```
现状：gap-c 已有"transition"评分维度
建议：在 N3.1 章节草稿 prompt 显式要求"开头【承接：上一章末状态】"
价值：让章节衔接更显式 · 与 dual-layer-archive 协同
风险：中（需修改 N3.x prompt · 触发 gap-c R1 红线）
```

### 借鉴 3 · 章节级 8 项自检

```
现状：fili-web 已有 ScoreCard 7 维 + P0-P3 4 级
建议：把 ScoreCard / P0-P3 压缩为类似"8 项 v2.0 checklist"的简洁清单
价值：用户更易记忆和应用
风险：低（仅 UI 简化）
```

### 借鉴 4 · 章节末尾固定 suffix

```
现状：fili-web 各 prompt 有自己的 suffix
建议：抽象出"通用末尾约束"（如不出戏 / 不破设定 / 不破调性）
价值：suffix 一致性
风险：低（仅 prompt 工程优化）
```

### 借鉴 5 · 字数控制更精细化

```
现状：fili-web 已按 chapter-words 控制
建议：可加入"每段字数预算"（如对话段 200-400 / 描写段 300-500）
价值：节奏更可控
风险：低
```
