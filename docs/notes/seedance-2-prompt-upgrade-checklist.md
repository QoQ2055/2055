## §1 · 6 大升级方向（v1.x → v2.0）

### 方向 1 · @素材引用（最核心新特性）

```
v1.x：长描述
  "穿白色长袖衬衫黑色西装裤的男性，带金边眼镜，提着深棕色公文包，
   在玻璃幕墙办公楼前的人行道上行走..."

v2.0：@素材引用
  @人物-林深 在 @场景-办公室门口 提着 @道具-公文包

原则：
  ├─ 穿插在描述中（不堆末尾）
  ├─ 命名格式：@类型-名字
  └─ 类型：@人物 / @场景 / @道具 / @音效 / @镜头
```

### 方向 2 · 时间分段格式（视频时长强制）

```
v1.x：一段长描述（无时间锚点）

v2.0：时间分段
  0-3秒：[启动] xxx
  3-6秒：[发展] xxx
  6-9秒：[高潮] xxx
  9-12秒：[落版] xxx

约束：
  ├─ 每镜 4-15 秒
  ├─ 总和 = 剧本时长（±10 秒）
  └─ 段标签格式：[标签] 描述
```

### 方向 3 · 双锚点【场景】+【承接】（视频连贯关键）

```
开头【场景】：
  ✅ 【场景：办公室·黄昏·暖光】
  含：地点 / 时间 / 光线 / 氛围

第 2 镜起【承接】：
  ✅ 【承接：上一帧 林深背对镜头·手伸向门把】
  含：人物位置 / 动作状态 / 摄像机角度

作用：
  ├─ 防止"换镜后人物瞬移"bug
  ├─ 防止"光线突变"bug
  └─ 让视频流畅过渡
```

### 方向 4 ·【对话："xxx"】格式（v2.0 强制要求）

```
v1.x：直白叙述
  林深说"你终于来了"

v2.0：明确格式
  林深转身【对话："你终于来了"】

作用：
  ├─ 让 AI 明确"哪部分是台词"（避免读出旁白）
  ├─ 让 AI 自动配口型
  └─ 让字幕/配音工具直接提取
```

### 方向 5 · 末尾固定 suffix（防崩防水印 · 必加）

```
每个 prompt 末尾必须追加：

（不生成字幕、4K高清、动作协调、电影级、画面不出现崩坏、
  人物场景和道具保持一致性、避免模糊低画质面部变形多余手指水印）

涵盖 9 项防崩：
  1. 不生成字幕
  2. 4K 高清
  3. 动作协调
  4. 电影级
  5. 画面不出现崩坏
  6. 人物场景和道具保持一致性
  7. 避免模糊
  8. 避免低画质 / 面部变形 / 多余手指
  9. 避免水印
```

### 方向 6 · 字数控制 100-200 字 / 镜

```
理由：
  ├─ token 浪费 ↓ · 模型推理稳定 ↑
  ├─ 过长 prompt 容易触发 AI"忽略前半部分"bug
  ├─ 过短 prompt 信息不足 · 生成质量低
  └─ 100-200 字 = 经验最优区间
```

## §2 · 8 项 prompt 自检 checklist

```
每个 v2.0 prompt 写完后必检：

□ [1] 用 @素材名 替代了长形容词描述？
□ [2] 时间分段（0-3s / 3-6s / ...）是否齐全？
□ [3] 开头有【场景：xxx】？
□ [4] 第 2 镜起有【承接：xxx】？
□ [5] 对话用【对话："xxx"】格式？
□ [6] 末尾加固定 suffix？
□ [7] 字数 100-200？
□ [8] 总时长 = 剧本时长（±10s）？

→ 8 项全过 = v2.0 合规
→ 缺 ≥ 2 项 = 视频生成质量风险高
```

## §3 · fili-web prompt vs Seedance 2.0 prompt 对照

```
fili-web 是小说创作工具 · Seedance 2.0 是视频生成工具。
两者都用 LLM · 但 prompt 工程目标不同。
但部分原则可类比：
```

| Seedance 2.0 | fili-web 对应 | 重叠度 | 备注 |
|---|---|:---:|---|
| @素材引用 | ProjectContext + artifacts 注入 | 80% | fili-web 用变量替换（{{title}} / {{ctx.genre}}）· 但不显式 @类型-名字 命名 |
| 时间分段 0-3s / 3-6s | 章节分段（按章 / 卷 / 段）| 50% | 颗粒度不同（秒 vs 章）· 但思路一致 |
| 双锚点【场景】+【承接】| gap-c 章节衔接评分（"承接"维度）| 70% | gap-c 已有 transition 维度 · 但未显式"承接锚点" |
| 【对话："xxx"】| N3.1/N3.2 已要求中文双引号「」 | 90% | fili-web 用「」· Seedance 用 ASCII 引号 · 思路一致 |
| 末尾固定 suffix | fili-web 各 prompt 已有 suffix | 80% | fili-web suffix 偏文学性约束 · Seedance 偏画质防崩 |
| 字数 100-200 | fili-web 各 prompt 字数更精细控制 | 90% | fili-web 按 chapter-words 计算 |

**平均重叠 ~77%** → fili-web 已隐式遵循类似原则。

## §10 · 写意图不写细节核心原则（v0.2 新增）★

> 来源：make-prompt-seedance2 README + 5 教程作者共识。
> 这是 Seedance 2.0 prompt 工程**最重要的 1 条原则** · 与 fili-web 也直接相关。

### 原则

```
在有"世界知识"的场景下：
  ✅ 推荐：写意图（一句话）· 让 AI 自动发挥导演 / 编剧思维
  ❌ 不推荐：写细节（每一步操作 / 每个画面）

例：
  ✅ 生产一个精美高级的兰州拉面广告，注意分镜编排
  ❌ 0-3 秒：揉面 / 3-6 秒：拉面 / 6-9 秒：浇汤...（束缚 AI）
```

### 何时适用 · 何时不适用

```
适用条件（一句话即可）：
  ✅ 有世界知识（餐饮品牌 / 健身 / 历史时期 / 通用流程）
  ✅ 不需要特定角色一致性
  ✅ 不需要特殊运镜风格

不适用条件（必须详细描述）：
  ❌ 需要保持角色形象一致（必须给参考图）
  ❌ 需要特殊运镜（必须给参考视频）
  ❌ 反常识场景（如猫会说话 · AI 没世界知识）
```

### 与 fili-web prompt 工程对接

```
fili-web 现有 prompt 设计：
  - N1.0 / N1.1 立意 / 框架：用户填【题材】【调性】【冲突】等结构化字段 ≈ 写意图
  - N3.1 章节草稿：详细 prompt 注入（artifacts / characterStates / scoreCard）≈ 写细节

借鉴方向：
  ✅ N1.x 已经隐式遵循"写意图不写细节"（结构化字段 + LLM 自由发挥）
  ✅ N3.x 也是该原则（注入上下文 + LLM 写章节）
  ⚠ 用户填字段时倾向"写细节" → fili-web 的 placeholder 设计应引导"写意图"
  ⚠ method modules 注入时不应过度约束 LLM（保留发挥空间）
```

## §11 · 平台限制 + 版权规避（v0.2 新增）

> 来源：make-prompt-seedance2 README · 仅 Seedance 2.0 平台特定 · fili-web 不直接受影响。
> 但作为 prompt 工程"边界知识"参考。

### Seedance 2.0 平台硬限制

| 项目 | 限制 |
|---|---|
| 真人脸部素材 | ❌ 不支持 |
| 文件总数 | ≤ 12 个（图片≤9 + 视频≤3 + 音频≤3）|
| 视频参考总时长 | ≤ 15 秒 |
| 音频格式 | 仅支持 MP3 |
| 生成分辨率 | 720P 为主 |

### 版权规避语法

```
场景：使用知名角色（如 IP 形象 / 名人）易被拒

规避方法：
  ❌ 不要直接写角色名字（如皮卡丘）
  ✅ 使用 Figure 1 / Figure 2 替代
  ✅ 描述外观特征（圆脸黄毛小动物 · 黑耳尖 · 红颊）
  ✅ 通过 @素材引用实际照片（用户合规上传）
```

### 与 fili-web 的关联（间接）

```
fili-web 不受 Seedance 平台限制 · 但 N3.x 章节生成时面对 LLM 同样需要：
  - 不直接抄已有 IP（侵权）
  - 用结构化字段（角色 Bible）替代直接命名
```
