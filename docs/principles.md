# fili-web · 产品哲学

> 写给 dogfooders / 维护者 / 未来的我自己 · 用于在 epic 设计 + skill 设计 + UI 决策时持续校准方向。
> 本文档**不写代码** · 只写**心态校准**。所有具体规则请见 `AGENTS.md` / `docs/planning/*` / `.windsurf/rules/`。

---

## §1 核心分工 · "好坏归人，对错归 AI"

人脑（左半区 · 感性）：
- 处理：**人性 / 情感 / 欲望 / 心动 / 热血**
- 任务：判断"这个人物是否有魅力？这段情节是否爽？这个梦是否动人？"
- 这是 AI 极弱的领域 · **不可能替代人**

AI（右半区 · 理性）：
- 处理：**结构 / 逻辑 / 节奏 / 字数 / 衔接 / 一致性**
- 任务：判断"大纲结构对不对？节奏踩没踩准节点？章节衔接是否硬切？"
- 这是 AI 极强的领域 · **绝对优势**

**fili-web 设计准绳**：

| 维度 | 决策方 | 工具支持 |
|---|:---:|---|
| 题材选择 / 调性定位 | 👤 人 | `novelTone` / `novelScale` 选项 |
| 情感曲线 / 角色魅力 | 👤 人 | CharacterBible 时间线（gap-b · 给人参考）|
| 情节走向 / 关键决策 | 👤 人 | PreviewModal 手动编辑 + 撤销栈 |
| 字数 / 章数 / 完成度 | 🤖 AI | ProgressDashboard（gap-d）|
| 结构合规 / 题材锚点 | 🤖 AI | ScoreCard 6 维（genre / method / kbRedline / craft）|
| 风格 / R1 对齐 | 🤖 AI | LLM 维度（r1Align / userKbStyle）|
| 衔接顺畅度 | 🤖 AI | gap-c transition 第 7 维 |

→ **任何 epic / skill 新设计前，先回答：这是"好坏"还是"对错"问题？**

## §2 工具进化论 · AI 不是物种替代

> 古人丢掉龟甲和刻刀，拿起毛笔和宣纸；
> 现代人丢掉纸和笔，拿起键盘与鼠标；
> 我们今天，把键盘换成更聪明的 AI。

**fili-web 不替代创作者**。它是**手中最趁手的神兵利器**：
- 提高效率（章节生成 / 评分 / 一致性检查自动化）
- 降低学习成本（method modules 把方法论"学会"了，用户只需选）
- 释放精力到创意（重复书写交给 AI，时间留给"造梦"）

→ **任何功能不要让用户离 AI 太远（懒得用）也不要太近（被支配）**。中间地带是用户作"导演 / 项目经理"。

## §3 三步工作流 · 人 → AI → 人

### Step 1 · 人（大脑）负责创意与方向

状态：充满激情和想象力的"造梦者"。

任务：设计核心创意 / 人物魅力点 / 故事走向 / 选择驱动模式。

fili-web 支持点：
- `novelHook` 字段（金手指 / 关键设定）
- `coreConflict` 字段（一句话冲突）
- 题材锚点选择（`genres`）
- method modules 选择（驱动 / 结构 / 角色法）

### Step 2 · AI（双手）负责快速原型搭建

状态：灵感最充沛时立刻"文字化"。

任务：根据用户选择的方法论 + 创意，快速生成结构严谨的初稿。

fili-web 支持点：
- N1.x 世界观 / 角色 bible 自动生成
- N2.x 分卷 / 分章自动生成
- N3.x 草稿 / 润色 LLM loop
- gap-c rollingContext 自动衔接

### Step 3 · 人（大脑）负责审视与修正

状态：从"创作者"切换为"审稿编辑"。

任务：用审美 + 经验对 AI 产出验证 / 优化。

fili-web 支持点：
- PreviewModal 章节预览 + ScoreCard 实时反馈
- ChapterValidationPanel 校验
- userKbFeedback 反馈循环
- gap-b CharacterBible 跨章节状态追踪
- 撤销栈（liveRefinementUndo）

→ **任何 UI 决策都应支持这 3 步快速切换 · 不让用户卡在某一步**。

## §4 创作 vs 编辑 · 距离感原则

**心理学原理**：人对自己一字一字敲出的文字会产生**主观美化**（"我写的多好啊"）。

AI 帮你生成的初稿与你之间天然有"距离感" → 你能像**审稿编辑**一样客观判断质量、发现问题。

→ **fili-web UX 应放大这个距离感优势**：
- 章节生成后**立即跳到 PreviewModal**（视角切换）
- ScoreCard 用客观分数对抗主观偏爱
- 撤销栈让用户敢于让 AI 大改（不怕弄丢"自己的字"）

---

## §5 反 AI 化的"AI 味"

> AI 生成的文本天然有"AI 味"：句式工整 / 形容词堆砌 / 情绪平 / 修辞重复。

**fili-web 防 AI 味手段**：
- `anti-ai-flavor` method module（已存在）
- userKbDocs `antiPattern` 类型（用户标"我不要这种风格"）
- ScoreCard `userKbStyle` 维度（与样本对齐度）

→ **任何 LLM prompt 设计都应考虑：会不会让生成更 AI 化？**

## §6 终极目标 · 创作者形态升级

```
v0 创作者形态：埋头苦干的工匠     · 全流程亲为 · 慢
v1 创作者形态：辅助工具用户       · 借助拼写检查 / 翻译 / 排版 · 中
v2 创作者形态：fili-web 用户     · 项目经理 · AI 团队 · 快  ★ 我们的目标
v3 创作者形态：AI 自闭环作家     · 全自动 · 无人 · 不要去这里
```

**v2 才是健康终点**：人是"专家审核 + 创意源 + 灵魂载体"，AI 是"无穷工人 + 质检员 + 备忘录"。

任何把用户推向 v3（"一键写完"）的功能 = **拒绝**。
